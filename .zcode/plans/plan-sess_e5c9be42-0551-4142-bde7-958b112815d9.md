## What I found that shapes the plan
- `package.json` start script uses `bun .next/standalone/server.js` — Railway nixpacks default to node/npm, so this needs adjusting.
- `prisma/schema.prisma` has **no `binaryTargets`** — Neon on Railway's linux-musl nixpack needs `["native", "linux-musl-openssl-3.0.x"]` or the Prisma query engine fails to load at runtime.
- No `postinstall` for `prisma generate` — Railway build will fail on `@prisma/client` import without it.
- `.gitignore` already excludes `.env*`, `.z-ai-config`, `node_modules`, `.next/`, logs. Need to add `db/` (the SQLite file dir) so it isn't committed.
- Seed route exists (`/api/seed`) and is gated by `ENABLE_SEED_ENDPOINT` — we'll use it to seed Neon once, then turn it off.
- `next.config.ts` has `output: "standalone"` + `ignoreBuildErrors: true` — good for Railway.

## Step-by-step

### 1. Prep the codebase for Postgres + Railway (local edits)
- **`prisma/schema.prisma`**: change `provider = "sqlite"` → `provider = "postgresql"`. Add `binaryTargets = ["native", "linux-musl-openssl-3.0.x"]` to the generator block. (This is the single most important change — without it the build/run breaks on Railway.)
- **`.gitignore`**: add `/db/` and `server.log`.
- **`package.json`**:
  - Add `"postinstall": "prisma generate"` (so Railway generates the client during build).
  - Make `start` node-compatible: `"start": "node .next/standalone/server.js"` (drop the `bun` dependency + `tee`).
  - Keep `build` as-is (standalone output + cp steps work on Railway).
- **No code changes needed** — all SQLite↔Postgres differences are absorbed by Prisma. (SQLite stored arrays as JSON strings; Postgres does too via the existing `String @default("[]")` columns, which Prisma treats as `text`. No migration of array columns needed since they're already JSON-stringified at the app layer.)

### 4. Deploy on Railway

## Risks / honest notes
- **Prisma on Neon via nixpacks** occasionally needs a different `binaryTargets` value depending on Railway's base image. I've specified `linux-musl-openssl-3.0.x` (the current Railway default); if the engine fails to load I'll adjust to `linux-musl` or `debian-openssl-3.0.x` based on the error.
- **The seed route is a security surface** — I'll set `ENABLE_SEED_ENDPOINT=false` immediately after seeding so it can't be hit publicly.
- **First deploy may take 5–8 min** (nixpack installs ~840 deps + builds Next 16 standalone). Subsequent deploys use the build cache.
- I will **not** commit `.env`, `.z-ai-config`, or `db/*.db` — all confirmed ignored or will be added to `.gitignore`.
